# V0.8 数据标准化流水线

## 目标

V0.8 开始，核销系统不把“上传 Excel”直接等同于“进入报表”。所有上传型模块统一经过：

`原始文件 → 原始数据层 → 字段映射 → 标准数据层 → 算法 → 报表`

这样后续平台、物流、采购、库存、费用、垫付、银行等原始资料即使列名不同，也只需要确认一次映射，报表算法不跟着原始文件格式变化。

## 关键原则

1. 原始文件永久归档，不修改。
2. 原始行逐行保留 `raw_json`，可追溯到上传批次和原文件。
3. 标准化后的记录单独存放，报表只能读取校验通过的标准记录。
4. 必需字段无法确认时，批次进入 `mapping_required`，系统不猜字段。
5. 映射方案可保存复用。
6. 销售出库仍只以旺店通为主数据源，手工调整不覆盖旺店通原值。
7. 品牌返利优先读取标准化采购单；0610 旧采购数据仅做兼容回退。

## 固定 API 路径（统一端口 8010）

- 模块目录：`GET /api/data/modules`
- 模块就绪状态：`GET /api/data/readiness`
- 模块标准字段：`GET /api/data/{module}/schema`
- 上传原始资料：`POST /api/data/{module}/upload`
- 上传批次：`GET /api/data/{module}/batches`
- 批次预览：`GET /api/data/batches/{batch_id}/preview`
- 字段映射并标准化：`POST /api/data/batches/{batch_id}/normalize`
- 标准数据：`GET /api/data/{module}/standard`
- 数据追溯：`GET /api/data/standard/{record_id}/lineage`

销售出库：

- 旺店通同步：`POST /api/data/sales-outbound/sync`
- 手工调整：`/api/data/sales-outbound/adjustments`
- RAW / Effective 对照：`GET /api/data/sales-outbound/effective`
- 调整汇总：`GET /api/data/sales-outbound/summary`

品牌返利：

- 规则：`/api/data/rebate/rules`
- 计算：`GET /api/data/rebate/calculate`

## 销售出库手工调整

支持范围：订单、店铺、平台、月份。

支持操作：

- `add`：增减
- `replace`：替换数值
- `multiply`：乘系数
- `text_replace`：替换文本
- `exclude`：排除核销
- `include`：恢复计入

每条调整必须填写原因。`raw` 永远是旺店通值，`effective` 才是报表口径值。

## 品牌返利

采购返利不再单纯依赖 0610 表里的返利结果，而是：

`标准化采购单 × 返利组成项规则`

同一采购单可叠加多个组成项，例如运营费、广告费、物流费、其他返利。每个组成项可有独立比例、税率系数和生效月份。

若同一组成项同时命中通配规则和品牌/渠道具体规则，只取优先级最高的一条，避免重复计算；不同组成项继续叠加。

## 模块接管规则

V0.8 不会把旧 0610 结果一次性全部替换。每个模块只有在：

1. 上传真实原始资料；
2. 字段标准化；
3. 算法完成；
4. 与旧表对数通过；

之后才切换为正式报表数据源。
