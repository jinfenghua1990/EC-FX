# V0.7 模块化数据中心

> **历史文档（2026-10-27 归档）**：本文写作时基于 NAS / 群晖 `8010`；项目现已独立运行于本机 `8050`，
> 与 NAS/8010 无关。以下群晖/8010 内容不再执行，也不作为验收或待办。

## 统一端口

群晖只开放一个 Web/API 端口：`8010`。不同业务模块通过固定路径区分，不再给每个模块单独开放 TCP 端口。

| 模块 | 主来源 | 固定接口 |
| --- | --- | --- |
| 销售出库 | 旺店通 API | `POST /api/data/sales-outbound/sync` |
| 销售出库手工调整 | 人工参数 | `GET/POST /api/data/sales-outbound/adjustments` |
| 销售出库有效值 | 旺店通原值 + 调整参数 | `GET /api/data/sales-outbound/effective?month=YYYY-MM` |
| 平台结算 | 原始文件 | `POST /api/data/platform-settlement/upload` |
| 物流费用 | 原始文件 | `POST /api/data/logistics/upload` |
| 采购单 | 原始文件 | `POST /api/data/purchase/upload` |
| 库存 | 原始文件 | `POST /api/data/inventory/upload` |
| 费用 | 原始文件 | `POST /api/data/expenses/upload` |
| 垫付 | 原始文件 | `POST /api/data/prepaid/upload` |
| 银行流水 | 原始文件 | `POST /api/data/bank/upload` |
| 品牌返利规则 | 可配置公式 | `GET/POST /api/data/rebate/rules` |
| 品牌返利计算 | 采购单 × 规则 | `GET /api/data/rebate/calculate?month=YYYY-MM` |

页面入口：`http://群晖IP:8010/modules`

## 原始数据与计算数据分离

所有上传文件先进入 `data/module-uploads/<module>/年/月/` 原始归档，同时逐行保留 `raw_json`。初次上传只进入 `raw_staged`，不猜字段、不直接写财务结果。每个模块等用户提供真实原始资料后再建立字段映射与算法，并用旧报表逐项对数。

## 销售出库调整原则

旺店通数据永远保留原值。人工调整单独写入 `manual_adjustments`，当前支持：

- 范围：订单 / 店铺 / 月份
- 数值：增减、替换
- 文本：替换店铺、平台、状态等
- 核销范围：排除 / 恢复计入
- 必填调整原因
- 可停用，不删除原始数据

报表后续统一读取 `effective` 值，而不是直接读取旺店通原值或把特殊逻辑写死到代码里。

## 品牌返利原则

品牌返利的业务基数是采购单，不是销售出库。返利规则表包含：

- 品牌
- 渠道
- 计算基数字段（采购发票未税 / 牌价未税 / 采购发票含税）
- 返利比例
- 税率系数
- 生效月份
- 优先级
- 说明

规则不在代码中写死。当前为兼容 0610 母表，`/api/data/rebate/calculate` 可对已经标准化进 `legacy_purchase_rows` 的采购数据做验证；后续收到采购原始资料后，将采购上传端口的 raw staging 映射到正式采购标准表，再由同一返利规则引擎计算。
